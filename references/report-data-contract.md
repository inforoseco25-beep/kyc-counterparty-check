# Контракт данных отчёта v1.1

Генератор принимает UTF-8 JSON по `schemas/report.schema.json`. Генератор компоновки не придумывает факты и не пересчитывает аналитические выводы.

## Обязательные блоки

- `metadata` - название, даты, версия, юрисдикция, достаточность и статус документа.
- `counterparty` - название, ИНН, ОГРН, КПП, роль и цель.
- `deal_profile` - режим оценки, полнота и существенные параметры сделки.
- `executive_summary` - балл, решение, вопрос, причины, риски и условия.
- `sources` - фактически использованные документы/источники.
- `source_coverage` - обязательные источники, факт проверки, качество и влияние пробела.
- `general_info`, `financial_analysis`, `legal_history`, `related_parties`, `specialized_analysis` - аналитические блоки.
- `risk_map` и `scores` - карта рисков и пять факторных оценок.
- `decision_conditions` - допустимость, эскалация и мониторинг.
- `documents_conditions` - документы, запросы, договорные условия и единое условие допуска.
- `control_matrix` - риск, договорный контроль, триггер, доказательство, владелец, мониторинг, последствие.
- `enhanced_due_diligence` и `limitations` - дальнейшие шаги и ограничения.

## Карточка сделки

`deal_profile.assessment_scope` принимает `preliminary` или `final`.

Обязательны: `completeness`, `subject`, `price`, `advance`, `stages`, `payment_terms`, `acceptance_terms`, `open_exposure`, `security`, `funding_source`, `missing_critical`, `proposed_limit`, `limit_basis`, `limit_approval`.

В режиме `preliminary` массив `missing_critical` не пуст, а отчёт содержит фразу «Предварительная KYC-оценка. Решение по конкретному договору не принято». Решение не может быть «Допустить».

Если `proposed_limit` содержит числовое значение, `limit_basis` должен ссылаться на реальную внутреннюю политику, параметры договора или финансовое согласование. Иначе используй «Не установлен» и `limit_approval: "Требует финансового согласования"`.

## Статусы доказательств

В JSON допустимы только:

- `primary_verified`;
- `document_verified`;
- `secondary_signal`;
- `conflict`;
- `not_confirmed`;
- `not_checked`;
- `source_unavailable`;
- `not_found`.

PDF преобразует коды в русские подписи. Технические коды не должны появляться на страницах.

## Правила текста

- Не вставляй HTML, Markdown, скрипты или CSS в значения.
- Не используй пустую строку вместо отсутствующих данных; объясняй причину.
- Денежные значения сопровождай валютой и единицей измерения.
- Все даты - `ДД.ММ.ГГГГ`, если источник не требует иного.
- Разные даты описывай хронологией; `conflict` используй только для несовместимых данных одного периода.
- Для коэффициентов указывай, что ориентиры индикативны, если нет отраслевой политики.

Для `findings` используй `tone`: `positive`, `warning`, `critical` или `neutral`. Для уровней риска: `Низкий`, `Умеренный`, `Повышенный`, `Высокий`, `Критический`.
