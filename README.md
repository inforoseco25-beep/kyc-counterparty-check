# kyc-counterparty-check

Skill для evidence-based KYC-проверки российского юридического лица или ИП по документам пользователя. Оценивает риск конкретного договора по шкале 1-10 и формирует корпоративный PDF-отчёт.

Skill предназначен для проверки заказчика или подрядчика. Он не заменяет санкционный скрининг, AML-проверку, иностранный due diligence, юридическое заключение или решение службы безопасности.

## Состав репозитория

- `SKILL.md` - основные инструкции и правила запуска;
- `agents/` - отображение skill в интерфейсе Codex;
- `references/` - методика, риск-модель, источники и контроль качества;
- `scripts/` - формирование и проверка PDF;
- `schemas/` - схема данных отчёта;
- `templates/` и `assets/` - оформление отчёта и шрифты;
- `examples/` - синтетические примеры без реальных контрагентов;
- `tests/` - тестовые сценарии;
- `docs/` - пользовательская инструкция в Word.

## Установка из GitHub

### Вариант 1. Через ZIP

1. На странице репозитория нажмите `Code` -> `Download ZIP`.
2. Распакуйте архив.
3. Скопируйте папку целиком в `%USERPROFILE%\.agents\skills\kyc-counterparty-check`.
4. Проверьте наличие `%USERPROFILE%\.agents\skills\kyc-counterparty-check\SKILL.md`.
5. Перезапустите Codex, если skill не появился сразу.

### Вариант 2. Через Git

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.agents\skills" | Out-Null
git clone https://github.com/inforoseco25-beep/kyc-counterparty-check.git "$env:USERPROFILE\.agents\skills\kyc-counterparty-check"
```

## Обновление установленного skill

Если skill был установлен командой `git clone` и вы не редактировали его локально:

```powershell
Set-Location "$env:USERPROFILE\.agents\skills\kyc-counterparty-check"
git status
git pull --ff-only
```

Если `git status` показывает изменённые файлы, сначала сохраните эти изменения отдельным коммитом или сделайте резервную копию. Не выполняйте принудительный сброс, если не понимаете, какие данные будут потеряны.

## Внесение изменений

Рекомендуемый рабочий процесс:

1. Получить последние изменения: `git pull --ff-only`.
2. Создать отдельную ветку: `git switch -c change/краткое-описание`.
3. Изменить нужные файлы.
4. Проверить изменения: `git status` и `git diff`.
5. Проверить структуру skill и выполнить тестовые сценарии.
6. Создать коммит и отправить ветку на GitHub.

```powershell
git add .
git commit -m "Кратко опишите изменение"
git push -u origin HEAD
```

После отправки откройте Pull Request на GitHub, проверьте список изменённых файлов и только затем объедините изменения с основной веткой `main`.

## Безопасность

- Не добавляйте в репозиторий папки `input`, `output`, реальные отчёты KYC, договоры и документы контрагентов.
- Не сохраняйте токены, пароли, ключи API и персональные данные в файлах репозитория.
- Примеры должны быть явно синтетическими.
- Перед публикацией проверяйте вкладку `Files changed` в Pull Request.
